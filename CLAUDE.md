# CLAUDE.md — zammad-mcp

**Company context comes first: read [../mojood-master/CLAUDE.md](../mojood-master/CLAUDE.md) and
[../mojood-master/STATUS.md](../mojood-master/STATUS.md), then this file.** Never add a `Co-Authored-By` line (or
any Claude attribution) to a commit message or a pull request description.

**What's here:** a Mojood Connect demo, built for one company (Zammad GmbH) to show them their product working
inside Claude. Six tools over Zammad's REST API; the two that change tickets need a confirmation code (`tools.py`);
no tool writes to a customer. A local Zammad in Docker (`docker/compose.yml` is Zammad's own, unchanged;
`docker/compose.override.yml`, `scripts/up.sh`, `scripts/setup.rb`, `scripts/reset.sh`) holds the SAMPLE support desk
of the made-up Harbor Trading (`seed.py`, times set by `scripts/backdate.rb`). Private until Hammad sends it; public
(Apache-2.0) after. Same recipe as `../snipeit-mcp`.

## Commands
```
scripts/reset.sh                         # fresh local Zammad + SAMPLE desk (Docker via Colima: `colima start`)
uv run --env-file .env zammad-mcp        # http://127.0.0.1:8003/mcp ; add --stdio for Claude Desktop
uv run --env-file .env pytest            # unit tests + live tests against the local Zammad
uvx ruff check --line-length 120 src tests
```

## Rules
- Secrets (`.env`, `docker/.env`: the API token, the admin and database passwords) are generated by `up.sh`,
  git-ignored, and never printed, copied into docs or chat.
- Everything in the data is SAMPLE and made up; no real company's data goes in.
- A change tool never acts without its confirmation code; keep the tests in `tests/test_tools.py` passing.
- Ticket numbers change with every reset (Zammad picks the prefix): never hard-code one outside a recorded session.
